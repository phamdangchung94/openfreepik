## Critical attack chain

`F3` or `F4` → inject `javascript:` URL through Freepik image/video render → executes in customer's browser → reads `localStorage["openfreepik-auth"]` → exfiltrates bearer code → drains customer quota AND admin can't trace it.

The Freepik image URLs in our flow come from:
- (a) Our own upload host (litterbox.catbox.moe) — out of our control if compromised
- (b) Freepik CDN response — should be safe but not enforced

## Recommended fix sequence

### Immediate (today, ~2h)
1. **F2 + F5 + F6 + F7**: add headers in `next.config.ts` (single 30-line block)
2. **F3 + F4**: tiny URL allowlist util used by both image and video components
3. **F8**: one-line cookie attribute change

### Next sprint (~4-6h)
4. **F1**: design httpOnly session for activation code. Trade-off: re-issue session token from server on `/api/activate`, store activationCode in encrypted session, use that as bearer to backend. Customer's machine never holds the raw activation code.

### Defer
5. **F9 + F10**: preventive only — track in backlog
