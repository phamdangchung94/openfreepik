# Code audit — 2026-05-04

## Summary
- 7 P0 findings, 12 P1, 14 P2
- Overall posture: the money-touching primitives (atomic charge, atomic refund, key pool with FOR-UPDATE) are well thought out, but the orchestrator wrapper around them has two silent-loss paths and several "documented but not wired" observability hooks. Public-launch-blocking bugs are concentrated in `src/lib/freepik/orchestrator.ts` (charge-without-customer-debit, taskId loss) and `src/app/api/download/[taskId]/route.ts` (open-proxy / leaks debug stack). Operationally there is no test coverage, no lint, no alerting, and several documented log events that are never emitted — five customers in, an outage will be invisible.

## Strengths (don't break these)

- **Atomic charge in `src/lib/auth/activation.ts:74-114`**: single `UPDATE … WHERE balance >= cost` with `or(unlimited, …)` and `or(no expiry, expiry > now())` is exactly right. No read-modify-write window. Refund uses `GREATEST(used - cost, 0)` so double-refunds clamp at zero rather than going negative. Don't refactor.
- **Key pool `pickActiveKey` (`src/lib/freepik/key-pool.ts:30-63`)**: CTE + `FOR UPDATE` + `UPDATE … FROM picked` is one statement, so the row-level lock is held for the whole pick-and-touch operation even on `neon-http` (which has no client-side transactions). Correctly avoids `SKIP LOCKED` based on prior audit; the comment documents why.
- **Orchestrator's CHARGE_INITIATED / CHARGE_COMMITTED log pair (`orchestrator.ts:120-165`)**: paired log events with a `requestId` are the correct primitive for "charged but didn't commit" reconciliation. Don't drop these. The `SLOW_CHARGE_WARN_MS = 5_000` watchdog at line 41 is a particularly nice touch — fires before Vercel's 10s timeout so the warning is visible even when the function dies mid-flight.
- **Login throttle UPSERT in `src/lib/auth/login-throttle.ts:105-131`**: single-statement INSERT … ON CONFLICT DO UPDATE with a CASE expression for both the counter reset and the lockout decision. Avoids a separate "reset counter" path. Don't replace with a transaction.
- **AES-GCM helper (`src/lib/crypto/aes-gcm.ts`)**: uses Web Crypto, validates 32-byte key length, IV-prepend layout is correct, encrypts/decrypts symmetrically without rolling its own auth tag. Solid.
- **Rate limiter UPSERT (`src/lib/rate-limit.ts:55-62`)**: bucket-key encoding (`<resource>:<scope>:<minuteBucket>`) means stale rows are auto-orphaned by time, and the `INSERT … ON CONFLICT DO UPDATE` is one-shot atomic. The `windowIdx` math is correct.
- **CSP in `next.config.ts`**: `default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, narrow image/media/connect allowlist. The acknowledged `unsafe-inline` for Next/Tailwind hot-reload is the right trade-off; don't loosen further.
- **`safeMediaUrl` in `src/lib/url-allowlist.ts`**: data:image/* + blob: + Freepik/Litterbox allowlist correctly rejects `javascript:` and arbitrary origins. Used for the `<img>`/`<video>` render path — keep it.
- **`isKeyExhaustedError` (`orchestrator.ts:256-262`)**: documented decision to treat 401+402 as exhausted-and-rotate. Correct intent (see P0-6 for the 403 caveat).
- **Concurrency-bounded poll fetcher (`src/lib/freepik/poll-task.ts:16-33`)**: client-side semaphore caps simultaneous polls to 5 globally so a 100-task batch can't overrun the 60/min server budget. Don't undo this.
- **Debounced localStorage in `src/store/task-store.ts:195-237`**: 500ms debounce on persist writes prevents 100-task batches from triggering 300+ sync writes. Don't replace with sync persist.
- **Download proxy 200-599 status guard (`src/app/api/download/[taskId]/route.ts:243-244`)**: defensive `safeStatus` check prevents a `Response` constructor RangeError on weird upstream statuses. Tiny but exactly the kind of thing that becomes a 500 in prod when you skip it.
- **Range header forwarding in download proxy**: pass-through enables seek/resume even when we're proxying. Don't strip it.
- **Generator form pricing preview is computed client-side from a fetched table, not from hard-coded constants** (`src/app/api/pricing/rates/route.ts`). Means an admin pricing edit propagates to the customer UI on next page load with no deploy. Good.
